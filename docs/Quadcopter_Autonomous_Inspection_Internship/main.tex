\section{Project Overview}

The \textbf{Quadcopter Autonomous Inspection Internship} introduces the complete chain of a modern autonomous aerial system. The project combines a simulated quadcopter, the PX4 flight stack, ROS 2 communication, Gazebo-based experimentation, onboard camera data, and YOLOv8 object detection to perform a structured inspection mission.

The mission is easy to state but technically rich: the quadcopter takes off, follows a planned trajectory, acquires images, identifies selected objects, associates detections with flight information, and produces evidence that the mission was performed correctly.

\section{Goals and Objectives}

\subsection{Technical objectives}

By the end of the internship, students should be able to:

\begin{itemize}
  \item explain the architecture of an autonomous quadcopter system;
  \item distinguish the responsibilities of Gazebo, PX4, ROS 2, and YOLOv8;
  \item use Ubuntu terminals to inspect, launch, monitor, and stop robotics processes;
  \item understand ROS 2 nodes, topics, services, parameters, launch files, and QoS;
  \item interpret PX4 local North-East-Down coordinates;
  \item understand how position and yaw references form a trajectory;
  \item run and modify a reproducible Gazebo inspection mission;
  \item bridge simulated camera images into ROS 2;
  \item interpret YOLOv8 classes, confidence values, bounding boxes, missed detections, and false detections;
  \item collect evidence using rosbags, logs, plots, and reports;
  \item compare desired and measured behavior with meaningful metrics;
  \item combine individual contributions into one coherent team demonstration.
\end{itemize}

\subsection{Educational objectives}

\begin{itemize}
  \item decompose an open problem into testable subsystems;
  \item make assumptions explicit and verify them experimentally;
  \item change one factor at a time when diagnosing behavior;
  \item treat failure as information when it is observed and understood;
  \item separate configuration, mathematics, control logic, monitoring, and evidence;
  \item write readable code and reproducible procedures;
  \item communicate technical choices and limitations honestly;
  \item collaborate through clear interfaces and individual accountability.
\end{itemize}

\section{Engineering and Physics Foundations}

\subsection{Coordinate frames}

PX4 local position uses North-East-Down:

\[
\mathbf{p}_{\mathrm{NED}}=
\begin{bmatrix}N&E&D\end{bmatrix}^{\mathsf T}.
\]

Positive vertical position points downward, so altitude $h$ above the local origin is commanded as $D=-h$. Visualization commonly uses East-North-Up:

\[
(x_{\mathrm{ENU}},y_{\mathrm{ENU}},z_{\mathrm{ENU}})=(E,N,-D).
\]

A numerically correct value in the wrong frame remains an incorrect engineering command.

\subsection{Circular inspection trajectory}

A horizontal orbit of radius $R$, centered at $(N_c,E_c)$, is

\[
N(t)=N_c+R\cos\theta(t),\qquad
E(t)=E_c+R\sin\theta(t),\qquad
D(t)=-h,
\]

with

\[
\theta(t)=\frac{2\pi t}{T}.
\]

The tangential speed and centripetal acceleration are

\[
v=\frac{2\pi R}{T},
\qquad
a_c=\frac{v^2}{R}=\frac{4\pi^2R}{T^2}.
\]

Halving the orbit period doubles the requested speed and multiplies the required centripetal acceleration by four.

\subsection{Smooth reference shaping}

The project uses

\[
s(u)=3u^2-2u^3,\qquad 0\le u\le1,
\]

because

\[
s(0)=0,\quad s(1)=1,\quad s'(0)=0,\quad s'(1)=0.
\]

The reference starts and ends with zero slope. PX4 remains responsible for feedback control.

\section{Teamwork and Individual Contribution}

Students work in one shared system while remaining accountable for an identifiable contribution. Contributions may cover mission requirements, trajectory analysis, ROS 2 integration, simulation design, perception, testing, data recording, or final demonstration coordination.

Each student maintains an engineering logbook that records the daily objective, learning, changes, tests, evidence, failures, decisions, next action, and contribution to integration.

\section{Testing, Evidence, and Safety}

For each experiment, students follow:

\begin{center}
\textbf{Claim $\rightarrow$ Setup $\rightarrow$ Controlled variable $\rightarrow$ Measurement $\rightarrow$ Result $\rightarrow$ Interpretation $\rightarrow$ Next test}
\end{center}

The default environment is simulation. Physical flight requires separate authorization, an approved area, a responsible operator, successful prior validation, and a recovery method. Manual keyboard control and autonomous offboard control must never command the vehicle simultaneously.
